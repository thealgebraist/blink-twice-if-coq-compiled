## 1. Normative Specification Requirements

The WHATWG Notifications API Standard defines the lifecycle, display, and replacement semantics of system notifications generated by web origins and Service Workers. Specifically, **§4.2 "Showing a notification"** governs how a newly created notification interacts with the existing list of active notifications managed by the user agent.

### 1.1 Normative Steps (Notifications API §4.2)
Given a new notification $n_{\text{new}}$ associated with an origin $O$ and an optional `tag` string $T$:

1. **Tag Evaluation:** Let `tag` be $n_{\text{new}}.\text{tag}$. A notification's tag defaults to the empty string `""` if not explicitly specified in `NotificationOptions`.
2. **Matching Condition:** If $n_{\text{new}}.\text{tag} \neq \text{""}$, the user agent must inspect the global list of active notifications $L$ to determine if there exists an active notification $n_{\text{old}} \in L$ such that:
   $$\text{origin}(n_{\text{old}}) = \text{origin}(n_{\text{new}}) \quad \land \quad \text{tag}(n_{\text{old}}) = \text{tag}(n_{\text{new}})$$
3. **Replacement Step (Tag Collision):** If such a matching notification $n_{\text{old}}$ exists:
   - Run the *replace a notification* steps for $n_{\text{old}}$ with $n_{\text{new}}$.
   - In the list of active notifications $L$, $n_{\text{new}}$ takes the exact positional slot occupied by $n_{\text{old}}$.
   - No new slot is allocated; the cardinality of the active notification list $|L|$ remains invariant.
   - If the platform does not natively support in-place notification updates, $n_{\text{old}}$ is closed (without firing the `close` event to the web page/Service Worker) and $n_{\text{new}}$ is shown immediately in its stead.
4. **Append Step (No Collision or Empty Tag):** If $n_{\text{new}}.\text{tag} = \text{""}$ or no matching notification $n_{\text{old}} \in L$ exists:
   - Append $n_{\text{new}}$ to the end of the list of active notifications $L$.
   - The cardinality of the active notification list increments by exactly 1: $|L'| = |L| + 1$.

### 1.2 Global Invariants Required by the Spec
- **Uniqueness of Tagged Notifications per Origin:** At any quiescent state of the notification subsystem, for any origin $O$ and any non-empty tag $T \neq \text{""}$, there is at most one notification $n \in L$ with $\text{origin}(n) = O$ and $\text{tag}(n) = T$.
- **Unbounded Untagged Notifications:** Notifications with $T = \text{""}$ never collide with one another, even if their origins and payloads are identical.

## 2. Chromium Blink Implementation & Invariants

In Chromium, notification display spans the Renderer process (`third_party/blink/renderer/modules/notifications/`) and the Browser process (`content/browser/notifications/`), communicating over the `blink::mojom::blink::NotificationService` Mojo interface.

### 2.1 `notification_manager.cc` Architecture
`blink::NotificationManager` (implemented in `third_party/blink/renderer/modules/notifications/notification_manager.cc`) serves as the per-`ExecutionContext` supplement that brokers all notification operations from both DOM contexts (`Notification` constructor) and Service Worker contexts (`ServiceWorkerRegistration.showNotification()`).

1. **Non-Persistent Notifications (`DisplayNonPersistentNotification`):**
   ```cpp
   void NotificationManager::DisplayNonPersistentNotification(
       const String& token,
       const WebNotificationData& notification_data,
       mojo::PendingRemote<mojom::blink::NotificationResourcesLoader> loader,
       mojo::PendingRemote<mojom::blink::NonPersistentNotificationListener> event_listener)
   ```
   - Blink validates that `token` is non-empty.
   - When `Notification::PrepareNotificationData` constructs `mojom::blink::NotificationData`, if the developer provides a non-empty `tag`, Blink serializes `tag` directly into the Mojo struct. If `tag` is empty, Blink's renderer layer (or downstream ` BlinkNotificationServiceImpl`) assigns a unique internal notification ID/token, whereas a non-empty `tag` deterministically maps to a single origin-scoped notification ID.

2. **Persistent Notifications (`DisplayPersistentNotification`):**
   ```cpp
   void NotificationManager::DisplayPersistentNotification(
       int64_t service_worker_registration_id,
       const WebNotificationData& notification_data,
       const WebNotificationResources& notification_resources,
       ScriptPromiseResolver<IDLUndefined>* resolver)
   ```
   - Invoked during Web Push processing (`push` event handler in Service Worker) or foreground Service Worker execution.
   - Forwards `notification_data` (containing `tag`) across the Mojo pipe to `NotificationService::DisplayPersistentNotification`.
   - In the browser process (`PlatformNotificationContextImpl` and `NotificationIdGenerator`), the persistent notification ID is deterministically derived from the tuple `(Origin, Tag)` when `!tag.empty()`, and from a monotonically increasing sequence number / UUID when `tag.empty()`.

3. **Retrieval & Filtering (`GetNotifications`):**
   ```cpp
   void NotificationManager::GetNotifications(
       int64_t service_worker_registration_id,
       const String& filter_tag,
       bool include_triggered,
       ScriptPromiseResolver<IDLSequence<Notification>>* resolver)
   ```
   - Queries the active notification list for a given `service_worker_registration_id` and `filter_tag`. Because replacement occurs atomically upon `DisplayPersistentNotification`, `GetNotifications` with a non-empty `filter_tag` is guaranteed to return a list of length $\le 1$.

### 2.2 Background Processing & Quota Invariants
When a Web Push message arrives in a Service Worker, Chromium enforces background budget and visible notification requirements (`userVisibleOnly: true`). Tag-based replacement preserves critical system invariants:
- **Anti-Spam / Bounded Queue Size:** By replacing existing notifications with matching `(origin, tag)` in-place, background sync and push handlers updating a live status (e.g., delivery tracking, chat thread summaries) do not grow the OS notification center queue size $|L|$.
- **Origin Isolation:** A Service Worker or frame from origin $O_1$ cannot overwrite or suppress a notification belonging to origin $O_2$, even if they specify identical non-empty tags.

## 3. Formal Specification in Rocq / Coq

Below is the complete, self-contained formalization of `BlinkNotificationTagReplacementSemantics.v`. We model origins, tags (`0` representing the empty tag `""`, and positive integers $t > 0$ representing non-empty string hashes/identifiers), notifications, and the replacement algorithm.

### 3.1 Definitions and Model

- `Origin`: Represented as `Z` (discrete origin identifier).
- `Tag`: Represented as `Z`. By convention, `tag = 0` denotes the empty string `""` (untagged), while `tag <> 0` denotes a valid non-empty developer tag.
- `Notification`: A record encapsulating `n_origin`, `n_tag`, and `n_payload` (representing title, body, badge, icon, and data).
- `same_origin_and_tag`: The exact boolean collision predicate from §4.2, evaluating to `true` if and only if both notifications share the same origin, share the same tag, and the tag is non-empty (`tag <> 0`).

## 4. Concrete Theorems and Complete Proofs (`BlinkNotificationTagReplacementSemantics.v`)

```coq
(** * BlinkNotificationTagReplacementSemantics.v
    Formal verification of WHATWG Notifications API §4.2 tag-based replacement
    semantics as implemented in Chromium Blink's notification_manager.cc. *)

From Coq Require Import ZArith.
From Coq Require Import Lia.
From Coq Require Import Bool.
From Coq Require Import List.
Import ListNotations.

Open Scope Z_scope.

(** ** 1. Data Types and Domain Model *)

Definition Origin := Z.
Definition Tag := Z.
Definition Payload := Z.

(** Tag = 0 models the empty string "" (no tag).
    Tag <> 0 models a non-empty tag string. *)
Definition is_non_empty_tag (t : Tag) : bool :=
  negb (Z.eqb t 0).

Record Notification : Type := mkNotification {
  n_origin  : Origin;
  n_tag     : Tag;
  n_payload : Payload
}.

Definition NotificationList := list Notification.

(** Collision predicate per Notifications API §4.2:
    Two notifications collide iff they have the same origin,
    the same tag, and the tag is non-empty. *)
Definition tag_collision (n1 n2 : Notification) : bool :=
  is_non_empty_tag (n_tag n1) &&
  Z.eqb (n_origin n1) (n_origin n2) &&
  Z.eqb (n_tag n1) (n_tag n2).

(** Check whether a list contains any notification colliding with [n]. *)
Fixpoint has_collision (n : Notification) (l : NotificationList) : bool :=
  match l with
  | [] => false
  | h :: t => if tag_collision n h then true else has_collision n t
  end.

(** Count occurrences of notifications matching origin [o] and tag [t]. *)
Fixpoint count_origin_tag (o : Origin) (t : Tag) (l : NotificationList) : nat :=
  match l with
  | [] => 0%nat
  | h :: tl =>
      if Z.eqb (n_origin h) o && Z.eqb (n_tag h) t
      then S (count_origin_tag o t tl)
      else count_origin_tag o t tl
  end.

(** ** 2. Notification Replacement and Show Semantics *)

(** Replace the first matching notification in-place, or append at the end
    if no matching notification exists (or if the tag is empty). *)
Fixpoint replace_or_append (n : Notification) (l : NotificationList) : NotificationList :=
  match l with
  | [] => [n]
  | h :: t =>
      if tag_collision n h
      then n :: t
      else h :: replace_or_append n t
  end.

(** The top-level show operation defined in NotificationManager. *)
Definition show (n : Notification) (l : NotificationList) : NotificationList :=
  replace_or_append n l.

(** Well-formedness invariant on the active notification list:
    For every origin [o] and every non-empty tag [t], there is at most one
    active notification in [l] with origin [o] and tag [t]. *)
Definition UniqueTaggedInvariant (l : NotificationList) : Prop :=
  forall (o : Origin) (t : Tag),
    is_non_empty_tag t = true ->
    (count_origin_tag o t l <= 1)%nat.

(** ** 3. Helper Lemmas *)

Lemma is_non_empty_tag_spec : forall t : Tag,
  is_non_empty_tag t = true <-> t <> 0.
Proof.
  intros t. unfold is_non_empty_tag.
  rewrite negb_true_iff.
  rewrite Z.eqb_neq.
  reflexivity.
Qed.

Lemma tag_collision_spec : forall n1 n2 : Notification,
  tag_collision n1 n2 = true <->
  (n_tag n1 <> 0 /\ n_origin n1 = n_origin n2 /\ n_tag n1 = n_tag n2).
Proof.
  intros n1 n2. unfold tag_collision.
  rewrite !andb_true_iff.
  rewrite is_non_empty_tag_spec.
  rewrite !Z.eqb_eq.
  tauto.
Qed.

Lemma tag_collision_false_spec : forall n1 n2 : Notification,
  tag_collision n1 n2 = false <->
  (n_tag n1 = 0 \/ n_origin n1 <> n_origin n2 \/ n_tag n1 <> n_tag n2).
Proof.
  intros n1 n2. unfold tag_collision.
  rewrite !andb_false_iff.
  unfold is_non_empty_tag.
  rewrite negb_false_iff.
  rewrite !Z.eqb_eq, !Z.eqb_neq.
  tauto.
Qed.

Lemma tag_collision_sym : forall n1 n2 : Notification,
  tag_collision n1 n2 = tag_collision n2 n1.
Proof.
  intros n1 n2.
  destruct (tag_collision n1 n2) eqn:E1;
  destruct (tag_collision n2 n1) eqn:E2; auto.
  - apply tag_collision_spec in E1.
    apply tag_collision_false_spec in E2.
    destruct E1 as [Hne [Ho Ht]].
    destruct E2 as [Hz | [Hno | Hnt]]; lia.
  - apply tag_collision_false_spec in E1.
    apply tag_collision_spec in E2.
    destruct E2 as [Hne [Ho Ht]].
    destruct E1 as [Hz | [Hno | Hnt]]; lia.
Qed.

(** Theorem 1: Canonical Equivalence
    show(n, l) is definitionally and extensionally equal to replace_or_append(n, l). *)
Theorem show_is_replace_or_append : forall (n : Notification) (l : NotificationList),
  show n l = replace_or_append n l.
Proof.
  intros n l. reflexivity.
Qed.
