## 1. Normative W3C/WICG Specification Requirements

In the W3C Accelerated Shape Detection in Images specification (§3, *Barcode Detection API*), the `BarcodeFormat` enumeration defines the set of supported 1D and 2D barcode symbologies recognized by the `BarcodeDetector` interface.

### 1.1 WebIDL Definition
```webidl
enum BarcodeFormat {
  "aztec",
  "code_128",
  "code_39",
  "code_93",
  "codabar",
  "data_matrix",
  "ean_13",
  "ean_8",
  "itf",
  "pdf417",
  "qr_code",
  "unknown",
  "upc_a",
  "upc_e"
};
```

### 1.2 Normative Invariants
1. **Totality of Representation:** Every valid `BarcodeFormat` string defined in the WebIDL must correspond to a distinct semantic state within the user agent's detection pipeline.
2. **Disjointness (Distinctness):** No two distinct `BarcodeFormat` enumeration identifiers may alias to the same underlying representation during options parsing (`BarcodeDetectorOptions.formats`), Mojo IPC serialization (`shape_detection.mojom.BarcodeFormat`), or result emission (`DetectedBarcode.format`).
3. **Unknown Format Handling:** While `"unknown"` is a valid WebIDL enum value for output (`DetectedBarcode.format` fallback), the conversion between the internal Mojo representation and the Blink V8 IDL representation must maintain strict injectivity and surjectivity over the defined domain to prevent cross-symbology spoofing or state corruption.

### 2.2 Critical Platform Invariants
1. **Exhaustive Switch Totality:** The C++ `switch` statement omits a `default:` branch deliberately so `-Wswitch` enforces compile-time exhaustiveness over the Mojo enum.
2. **Integer Backing Injectivity:** In both `V8BarcodeFormat::Enum` (generated by the Blink IDL compiler) and `shape_detection::mojom::blink::BarcodeFormat` (generated by the Mojo compiler), each enumerator is assigned a unique `int32_t` / `uint32_t` discriminant in $[0, 13]$.
3. **Deduplication Correctness:** When `BarcodeDetector::getSupportedFormats()` or the `BarcodeDetector` constructor filters and deduplicates requested formats using `WTF::Vector` or `WTF::HashSet`, correctness depends entirely on the injectivity of the enum-to-integer mapping.

(** Boolean equality for BarcodeFormat. *)
Definition barcode_format_eqb (x y : BarcodeFormat) : bool :=

(** Theorem 4: Primary Property - barcode_format_distinct (Injectivity).
    Distinct BarcodeFormat enum values map to strictly distinct integers,
    and equal integer mappings imply identical enum values. *)
Theorem barcode_format_distinct : forall (f1 f2 : BarcodeFormat),
  format_to_Z f1 = format_to_Z f2 -> f1 = f2.
Proof.
  intros f1 f2 Heq.

  rewrite !format_Z_roundtrip in Heq.
  inversion Heq.
  reflexivity.
Qed.

(** Corollary 4.1: Contrapositive Distinctness.

  f1 <> f2 -> format_to_Z f1 <> format_to_Z f2.
Proof.
  intros f1 f2 Hneq Heq.
  apply Hneq.
  apply barcode_format_distinct.
  exact Heq.
