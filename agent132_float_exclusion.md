### 1. Chromium Blink Float Positioning vs. CSS 2.1 §9.5.1

In Chromium’s Blink LayoutNG engine, float placement and inline space reduction are governed by the interaction between the `NGExclusionSpace` and the `NGInlineLayoutAlgorithm`. These components enforce the geometrical constraints defined in CSS 2.1 §9.5.1 (Positioning the float: the 'float' property).

#### Left and Right Float Placement at Container Boundary
* **CSS 2.1 §9.5.1 Rule 1 & Rule 4:** A left-floating box must have its left outer edge touch the left edge of its containing block (or the right outer edge of a preceding left float). Its top may not be higher than the top of its containing block.
* **Blink LayoutNG Implementation (`ng_unpositioned_float.cc`, `ng_exclusion_space.cc`):** 
  When the `NGBlockLayoutAlgorithm` or `NGInlineLayoutAlgorithm` encounters a floating object, it constructs an `NGUnpositionedFloat`. It queries the current `NGExclusionSpace` via `FindLayoutOpportunity()`. 
  If no prior exclusions exist at the current Block Progression Offset (BFC block offset), a left float is placed at `bfc_offset.inline_offset = container_builder.BfcInlineOffset() + content_edge_offset`, aligning it flush with the containing block's start edge. Right floats align flush with `container_width - float_inline_size`. The resulting physical box is wrapped in an `NGExclusion` structure and appended to the immutable `NGExclusionSpace`, yielding a new state for subsequent layout passes.

#### Available Inline Space Reduction for Subsequent Inline Boxes
* **CSS 2.1 §9.5 wrap behavior:** Line boxes next to a float are shortened to make room for the margin box of the float.
* **Blink LayoutNG Implementation (`ng_inline_layout_algorithm.cc`, `ng_layout_opportunity.h`):**
  Before constructing a line box, `NGInlineLayoutAlgorithm::CreateLine()` queries the `NGExclusionSpace` for an `NGLayoutOpportunity` at the current BFC block offset (cursor Y) with a minimum inline size requirement (often 0 initially, then adjusted for the first inline item). 
  The `NGExclusionSpace` projects all active float exclusions that intersect the vertical interval `[cursor_y, cursor_y + line_height]`. It computes the continuous horizontal interval `[start_inline_offset, end_inline_offset]` unblocked by left and right floats. The line box's available inline size is strictly reduced to `end_inline_offset - start_inline_offset`.

### 2. Core Layout Invariants

To verify the soundness of Blink's exclusion space geometry against CSS 2.1 §9.5.1, we isolate three core arithmetic invariants:

1. **Line Box Inline Size Reduction Invariant:**
   For any line box vertically intersecting a set of active floats without dropping below them, the available inline size $W_{\text{line}}$ is bounded by the container inline size $W_{\text{container}}$ minus the sum of the widths of the intersecting left and right floats:
   $$W_{\text{line}} = \max(0, W_{\text{container}} - (W_{\text{float\_left}} + W_{\text{float\_right}}))$$
   *(In the single-float regime where $W_{\text{container}} \ge W_{\text{float}}$, this simplifies strictly to $W_{\text{line}} = W_{\text{container}} - W_{\text{float}}$).*

2. **Float Monotonicity / Y-Cursor Invariant (CSS 2.1 §9.5.1 Rule 6):**
   The outer top of a floating box ($Y_{\text{float}}$) may not be higher than the top of any line-box containing a box generated by an element earlier in the source document ($Y_{\text{cursor}}$). In Blink's BFC coordinate system (where $Y$ grows downward):
   $$Y_{\text{float}} \ge Y_{\text{cursor}}$$

3. **Line Box Non-Negativity Invariant:**
   An `NGLayoutOpportunity` cannot yield a negative inline size. Even if the margin box of a float exceeds the containing block's inline size ($W_{\text{float}} > W_{\text{container}}$), the computed available inline space for the line box is clamped to zero:
   $$W_{\text{line}} \ge 0$$

### 3. Rocq / Coq Formalization (`BlinkFloatExclusionSemantics.v`)

The following file is a complete, self-contained Rocq (Coq) formalization using `ZArith` and `Lia` that models the `NGExclusionSpace` state transitions and mechanically proves the three core invariants.

```coq
(** * BlinkFloatExclusionSemantics.v
    Formal verification of Chromium Blink LayoutNG Float Positioning 
    and Exclusion Space geometry against CSS 2.1 §9.5.1. *)

Require Import Coq.ZArith.ZArith.
Require Import Coq.Lists.List.
Require Import Coq.micromega.Lia.
Import ListNotations.

Open Scope Z_scope.

(** ** 1. Basic Types and Geometry *)

(** Polarity of the CSS float property *)
Inductive FloatType : Type :=
  | FloatLeft
  | FloatRight.

(** Represents a positioned float exclusion in the BFC (Block Formatting Context).
    Corresponds to Blink's [NGExclusion] struct. *)
Record FloatBox : Type := mkFloatBox {
  fb_type : FloatType;
  fb_x : Z;          (* Inline start offset *)
  fb_y : Z;          (* Block start offset (top edge) *)
  fb_width : Z;      (* Margin-box inline size *)
  fb_height : Z      (* Margin-box block size *)
}.

(** Represents the layout state during inline/block formatting.
    Corresponds to Blink's [NGExclusionSpace] + BFC Offset cursor. *)
Record LayoutState : Type := mkLayoutState {
  container_width : Z;
  cursor_y : Z;
  placed_floats : list FloatBox
}.

(** Represents a continuous horizontal region available for a line box.
    Corresponds to Blink's [NGLayoutOpportunity]. *)
Record LineBoxOpportunity : Type := mkLineBoxOpportunity {
  line_x_start : Z;
  line_x_end : Z;
  line_y : Z
}.

(** Inline size of a layout opportunity, clamped to 0 to prevent negative widths. *)
Definition line_inline_size (opp : LineBoxOpportunity) : Z :=
  Z.max 0 (line_x_end opp - line_x_start opp).

(** ** 2. Float Placement & Space Reduction Semantics *)

(** Places a single float at the current cursor_y, flush with the container boundary.
    Models the base case of [NGExclusionSpace::FindLayoutOpportunity] when placing a float. *)
Definition place_float_at_boundary 
  (st : LayoutState) (ftype : FloatType) (fwidth fheight : Z) (y_offset : Z) : LayoutState * FloatBox :=
  let actual_y := Z.max (cursor_y st) y_offset in
  let x_pos := match ftype with
               | FloatLeft => 0
               | FloatRight => container_width st - fwidth
               end in
  let new_float := mkFloatBox ftype x_pos actual_y fwidth fheight in
  let new_state := mkLayoutState (container_width st) (cursor_y st) (new_float :: placed_floats st) in
  (new_state, new_float).

(** Computes the available inline space at [y] in the presence of a single active float.
    Models [NGInlineLayoutAlgorithm] querying [NGExclusionSpace]. *)
Definition compute_line_opportunity_single (c_width : Z) (f : FloatBox) (y : Z) : LineBoxOpportunity :=
  (* Check if the vertical position [y] intersects the float's block interval *)
  if (fb_y f <=? y) && (y <? fb_y f + fb_height f) then
    match fb_type f with
    | FloatLeft => mkLineBoxOpportunity (fb_width f) c_width y
    | FloatRight => mkLineBoxOpportunity 0 (c_width - fb_width f) y
    end
  else
    mkLineBoxOpportunity 0 c_width y.

(** ** 3. Formal Verification of CSS 2.1 §9.5.1 Invariants *)

(** *** Invariant 1: Line Box Inline Size Reduction
    Proves that when a line box vertically intersects an active float (and the float
    fits within the container), the resulting line box inline size is exactly 
    [container_width - float_width]. *)
Theorem line_box_inline_size_reduction :
  forall (st : LayoutState) (ftype : FloatType) (fw fh y_off : Z) (st' : LayoutState) (f : FloatBox),
    0 <= fw <= container_width st ->
    0 < fh ->
    place_float_at_boundary st ftype fw fh y_off = (st', f) ->
    let opp := compute_line_opportunity_single (container_width st') f (fb_y f) in
    line_inline_size opp = container_width st - fw.
Proof.
  intros st ftype fw fh y_off st' f H_width H_height H_place opp.
  unfold place_float_at_boundary in H_place.
  inversion H_place as [[H_st' H_f]].
  subst st' f opp.
  unfold compute_line_opportunity_single, line_inline_size.
  simpl.
  (* Prove that fb_y f intersects [fb_y f, fb_y f + fh) *)
  assert (H_cond : (Z.max (cursor_y st) y_off <=? Z.max (cursor_y st) y_off) &&
                   (Z.max (cursor_y st) y_off <? Z.max (cursor_y st) y_off + fh) = true).
  {
    apply andb_true_iff. split.
    - apply Z.leb_refl.
    - apply Z.ltb_lt. lia.
  }
  rewrite H_cond.
  destruct ftype; simpl; lia.
Qed.

(** *** Invariant 2: Float Y >= Current Cursor (CSS 2.1 §9.5.1 Rule 6)
    Proves that a newly placed float's top edge (fb_y) is never placed higher 
    (at a smaller Y coordinate) than the current BFC block offset cursor. *)
Theorem float_y_ge_cursor :
  forall (st : LayoutState) (ftype : FloatType) (fw fh y_off : Z) (st' : LayoutState) (f : FloatBox),
    place_float_at_boundary st ftype fw fh y_off = (st', f) ->
    fb_y f >= cursor_y st.
Proof.
  intros st ftype fw fh y_off st' f H_place.
  unfold place_float_at_boundary in H_place.
  inversion H_place as [[H_st' H_f]].
  subst f. simpl.
  lia.
Qed.

(** *** Invariant 3: Line Box Non-Negativity
    Proves that for any container width, float geometry, and vertical cursor,
    the computed inline size of a line box is never negative, even if the float
    is wider than the container itself. *)
Theorem line_box_non_negative :
  forall (c_width : Z) (f : FloatBox) (y : Z),
    line_inline_size (compute_line_opportunity_single c_width f y) >= 0.
Proof.
  intros c_width f y.
  unfold line_inline_size.
  lia.
Qed.

(** *** Bonus Invariant: Container Boundary Alignment (CSS 2.1 §9.5.1 Rule 1)
    Proves that a left float's left outer edge touches the left edge of the container (0),
    and a right float's right outer edge touches the right edge of the container. *)
Theorem float_boundary_alignment :
  forall (st : LayoutState) (ftype : FloatType) (fw fh y_off : Z) (st' : LayoutState) (f : FloatBox),
    place_float_at_boundary st ftype fw fh y_off = (st', f) ->
    match ftype with
    | FloatLeft => fb_x f = 0
    | FloatRight => fb_x f + fb_width f = container_width st
    end.
Proof.
  intros st ftype fw fh y_off st' f H_place.
  unfold place_float_at_boundary in H_place.
  inversion H_place as [[H_st' H_f]].
  subst f. simpl.
  destruct ftype; lia.
Qed.
```
