## 1. Normative W3C CSS Flexbox Specification Requirements

According to the **CSS Flexible Box Layout Module Level 1, Section 5.4 ("Display Order: the `order` property")**:

> *"Flex items are, by default, displayed and laid out in the same order as they appear in the source document. The `order` property may be used to change this ordering."*
> 
> *"The `order` property controls the order in which flex items appear within the flex container, by assigning them to ordinal groups. It takes a single `<integer>` value, which specifies which ordinal group the flex item belongs to."*
> 
> *"A flex container lays out its content in order-modified document order, starting from the lowest numbered ordinal group and going up. Items with the same ordinal group are laid out in the order they appear in the source document."*

### Formal Normative Invariants
Let $I = [x_0, x_1, \dots, x_{n-1}]$ be the sequence of flex items generated by a flex container, indexed by their strict source document tree order $dom\_index(x_k) = k$, where $k \in \mathbb{N}$ and $i < j \implies dom\_index(x_i) < dom\_index(x_j)$.

Each flex item $x$ has a computed CSS `order` property $order(x) \in \mathbb{Z}$ (defaulting to $0$).

The **order-modified document order** is a permutation $I' = \pi(I)$ such that for all indices $a < b$ in $I'$:
1. **Primary Ordinal Group Ordering:** $order(I'[a]) \le order(I'[b])$.
2. **Tie-Breaking (Stability / Document Order Preservation):** If $order(I'[a]) = order(I'[b])$, then $dom\_index(I'[a]) < dom\_index(I'[b])$.

Mathematically, this establishes a strict total order $<_{\text{flex}}$ on flex items via a lexicographical comparison of the key:
$$\text{order\_key}(x) = (order(x), dom\_index(x)) \in \mathbb{Z} \times \mathbb{Z}$$
where $(o_1, d_1) <_{\text{lex}} (o_2, d_2) \iff (o_1 < o_2) \lor (o_1 = o_2 \land d_1 < d_2)$.

## 2. Chromium Blink Implementation Details & Invariants

In Chromium Blink’s LayoutNG architecture, flex item enumeration and `order`-modified document traversal are governed by `FlexItemIterator` in `third_party/blink/renderer/core/layout/flex/flex_item_iterator.cc` (historically coupled with `OrderIterator` in `order_iterator.cc`).

### Blink Traversal Mechanism
Instead of materializing an array of all children and invoking `std::stable_sort` unconditionally on every layout pass, Blink optimizes for the common case (all `order == 0`) while guaranteeing exact equivalence to a stable sort when multiple `order` values exist:

1. **Collection of Distinct Ordinal Groups (`order_values_`):**
   During child box collection or pre-traversal, Blink records the CSS `ComputedStyle::Order()` (`int32_t`) of each child into a set/vector of unique values. This vector of unique integers is sorted in strictly ascending order: $v_0 < v_1 < \dots < v_{m-1}$.
2. **Multi-Pass / Bucketed Document-Order Iteration:**
   `FlexItemIterator::NextItem()` iterates through the sorted unique `order` values $v_k$. For a fixed target ordinal group $v_k$, it scans the flex container's immediate layout children in their native linked-list DOM / box-tree sequence (`LayoutObject::NextSibling()`).
3. **Emission Condition:**
   During pass $k$, a child $x$ is yielded if and only if `x->StyleRef().Order() == v_k`.

### Blink Implementation Invariants
* **Invariant B1 (DOM Index Monotonicity):** Sibling traversal via `NextSibling()` visits nodes in strictly increasing `dom_index` order ($d_0 < d_1 < \dots < d_{n-1}$).
* **Invariant B2 (Completeness & Partitioning):** Every flex item has a well-defined integer `order` property that belongs to the sorted unique set of collected order values.
* **Invariant B3 (Equivalence to Lexicographical Stable Sort):** Iterating over strictly increasing unique `order` buckets $v_0 < v_1 < \dots < v_{m-1}$ and filtering the strictly increasing `dom_index` sibling list per bucket is extensionally equal to sorting the initial document list using a stable insertion/merge sort keyed on `order(x)`, which in turn is uniquely determined by the strict total order on $\text{order\_key}(x) = (order(x), dom\_index(x))$.

```coq
(** * BlinkFlexItemOrderPropertySortingSemantics.v
    Formal Verification of W3C CSS Flexbox §5.4 `order` Property Stable Sorting
    and Chromium Blink `flex_item_iterator.cc` Semantics.
*)

From Coq Require Import ZArith.
From Coq Require Import Lia.
From Coq Require Import List.
From Coq Require Import Bool.
From Coq Require Import Permutation.
From Coq Require Import Sorting.Sorted.
Import ListNotations.
Open Scope Z_scope.

(** ** 1. Data Types and Key Projections *)

Record FlexItem : Type := mkFlexItem {
  item_id   : Z;
  order     : Z;
  dom_index : Z
}.

Definition order_key (x : FlexItem) : Z * Z :=
  (order x, dom_index x).

(** ** 2. Lexicographical Order Relations *)

Definition lex_le (x y : FlexItem) : Prop :=
  order x < order y \/ (order x = order y /\ dom_index x <= dom_index y).

Definition lex_lt (x y : FlexItem) : Prop :=
  order x < order y \/ (order x = order y /\ dom_index x < dom_index y).

(** Boolean comparison used by stable insertion sort:
    Returns true iff x should precede or stay before y when x appears before y. *)
Definition order_leb (x y : FlexItem) : bool :=
  (order x <=? order y).

Lemma order_leb_spec : forall x y,
  order_leb x y = true <-> order x <= order y.
Proof.
  intros x y. unfold order_leb. apply Z.leb_le.
Qed.

Lemma order_leb_false_spec : forall x y,
  order_leb x y = false <-> order y < order x.
Proof.
  intros x y. unfold order_leb. rewrite Z.leb_gt. split; lia.
Qed.

(** ** 3. Fundamental Properties of Lexicographical Order *)

Theorem lex_le_refl : forall x, lex_le x x.
Proof.
  intro x. unfold lex_le. right. split; lia.
Qed.

Theorem lex_le_trans : forall x y z,
  lex_le x y -> lex_le y z -> lex_le x z.
Proof.
  intros x y z Hxy Hyz.
  unfold lex_le in *.
  destruct Hxy as [H1 | [H1a H1b]];
  destruct Hyz as [H2 | [H2a H2b]];
  try (left; lia);
  try (right; split; lia).
Qed.

Theorem lex_lt_trans : forall x y z,
  lex_lt x y -> lex_lt y z -> lex_lt x z.
Proof.
  intros x y z Hxy Hyz.
  unfold lex_lt in *.
  destruct Hxy as [H1 | [H1a H1b]];
  destruct Hyz as [H2 | [H2a H2b]];
  try (left; lia);
  try (right; split; lia).
Qed.

Theorem lex_lt_irrefl : forall x, ~ lex_lt x x.
Proof.
  intros x H. unfold lex_lt in H. lia.
Qed.

Theorem lex_lt_le_weak : forall x y, lex_lt x y -> lex_le x y.
Proof.
  intros x y H. unfold lex_lt in H. unfold lex_le.
  destruct H as [H | [H1 H2]]; [left; lia | right; split; lia].
Qed.

Theorem order_key_injective : forall x y,
  order_key x = order_key y ->
  order x = order y /\ dom_index x = dom_index y.
Proof.
  intros x y H. unfold order_key in H.
  inversion H. split; reflexivity.
Qed.

Theorem lex_lt_antisym : forall x y,
  lex_lt x y -> lex_lt y x -> False.
Proof.
  intros x y H1 H2. unfold lex_lt in *. lia.
Qed.

(** ** 4. Document Order Well-Formedness Predicates *)

(** A list of flex items is in strict source document order if `dom_index`
    is strictly increasing along the list. *)
Inductive DocOrdered : list FlexItem -> Prop :=
  | DocOrdered_nil  : DocOrdered []
  | DocOrdered_cons : forall x l,
      DocOrdered l ->
      Forall (fun y => dom_index x < dom_index y) l ->
      DocOrdered (x :: l).

(** A list of flex items is in CSS §5.4 order-modified document order if
    `lex_lt` holds pairwise along the list. *)
Inductive FlexOrdered : list FlexItem -> Prop :=
  | FlexOrdered_nil  : FlexOrdered []
  | FlexOrdered_cons : forall x l,
      FlexOrdered l ->
      Forall (fun y => lex_lt x y) l ->
      FlexOrdered (x :: l).

(** ** 5. Stable Insertion Sort Specification *)

(** Inserting `x` (which originates *before* all elements of `l` in DOM order)
    into an already-sorted list `l`. Because `x` precedes elements of `l` in DOM
    order, if `order x <= order y`, `x` must be placed before `y` to preserve
    document order on ties. *)
Fixpoint insert_item (x : FlexItem) (l : list FlexItem) : list FlexItem :=
  match l with
  | [] => [x]
  | y :: ys =>
      if order_leb x y then x :: y :: ys
      else y :: insert_item x ys
  end.

Fixpoint stable_sort_by_order (l : list FlexItem) : list FlexItem :=
  match l with
  | [] => []
  | x :: xs => insert_item x (stable_sort_by_order xs)
  end.

(** ** 6. Permutation & Membership Invariants *)

Lemma insert_item_perm : forall x l,
  Permutation (insert_item x l) (x :: l).
Proof.
  intros x l. induction l as [| y ys IH]; simpl.
  - apply Permutation_refl.
  - destruct (order_leb x y) eqn:Heq.
    + apply Permutation_refl.
    + apply perm_trans with (y :: x :: ys).
      * apply perm_skip. exact IH.
      * apply perm_swap.
Qed.

Theorem stable_sort_perm : forall l,
  Permutation (stable_sort_by_order l) l.
Proof.
  induction l as [| x xs IH]; simpl.
  - apply Permutation_refl.
  - apply perm_trans with (x :: stable_sort_by_order xs).
    + apply insert_item_perm.
    + apply perm_skip. exact IH.
Qed.

Lemma insert_item_In : forall x y l,
  In y (insert_item x l) <-> y = x \/ In y l.
Proof.
  intros x y l.
  pose proof (insert_item_perm x l) as Hperm.
  split; intro H.
  - apply Permutation_in with (l := insert_item x l) in H; [| exact Hperm].
    simpl in H. exact H.
  - apply Permutation_in with (l := x :: l); [apply Permutation_sym; exact Hperm |].
    simpl. exact H.
Qed.

Theorem stable_sort_In : forall x l,
  In x (stable_sort_by_order l) <-> In x l.
Proof.
  intros x l.
  pose proof (stable_sort_perm l) as Hperm.
  split; intro H.
  - eapply Permutation_in; [exact Hperm | exact H].
  - eapply Permutation_in; [apply Permutation_sym; exact Hperm | exact H].
Qed.

Lemma Forall_insert_item : forall (P : FlexItem -> Prop) x l,
  P x -> Forall P l -> Forall P (insert_item x l).
Proof.
  intros P x l Hx Hl.
  rewrite Forall_forall in *.
  intros z Hz.
  apply insert_item_In in Hz.
  destruct Hz as [-> | Hz]; [exact Hx | apply Hl; exact Hz].
Qed.
