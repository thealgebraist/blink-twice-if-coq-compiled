**Agent:** 400
**Target:** HTML Popover API — `::backdrop` Pseudo-element Coverage Bounds
**Focus:** Full Viewport Coverage Architecture & Edge-Case Verification

---

### 1. Executive Summary
The `::backdrop` pseudo-element, when generated by an open Popover element (`popover-open`) in the Top Layer, is mandated by the CSS Position Layout Level 4 specification to cover the entirety of the viewport. In Blink, this is achieved through Default User Agent (UA) styles combined with specialized LayoutObject positioning logic that anchors the element to the **LayoutView** (the Initial Containing Block), bypassing standard DOM ancestor containment constraints.

### 2. User Agent Stylesheet Baseline
In `third_party/blink/renderer/core/html/resources/html.css`, the baseline geometry for the popover backdrop is defined to force full viewport dimensions:

```css
[popover]:popover-open::backdrop {
    position: fixed;
    inset: 0; /* top: 0; right: 0; bottom: 0; left: 0; */
    width: auto; 
    height: auto;
    pointer-events: none; /* Note: Dialog backdrops trap clicks; Popover backdrops allow click-through for light-dismiss */
    background-color: transparent;
}
```
*Audit Note:* `width` and `height` resolve to `100%` of the containing block via `inset: 0` on a `position: fixed` element.

### 3. Blink Layout & Containment Architecture
Standard `position: fixed` elements lose full viewport coverage if an ancestor defines a `transform`, `perspective`, `filter`, or `contain: paint/layout`. 

**Blink Resolution:**
1. **Top Layer Promotion:** When `HTMLElement::ShowPopoverInternal()` executes, both the popover and its `::backdrop` are promoted to the `Document::TopLayerElements()`.
2. **Containing Block Override:** In `LayoutObject::ContainingBlock()`, Blink intercepts elements rendered in the top layer (including `kPseudoIdBackdrop`).
3. **LayoutView Anchoring:** Regardless of where the popover resides in the DOM tree, the `::backdrop`'s containing block is explicitly assigned to the `LayoutView`. This guarantees the `inset: 0` coordinates map strictly to the root viewport bounds, immune to ancestor CSS transforms or `overflow: hidden` clipping.

### 4. Viewport Metric & Edge-Case Analysis

#### A. Visual vs. Layout Viewport (Pinch-Zoom & Mobile URL Bars)
* **Mechanism:** `position: fixed` attaches to the **Layout Viewport**.
* **Mobile Dynamic Viewport:** As the mobile browser URL bar retracts/expands, the Layout Viewport dynamically resizes. The `::backdrop` correlates to `100dvw` / `100dvh` (Dynamic Viewport) via `inset: 0`, ensuring no unpainted gaps appear at the bottom of the screen during scroll-induced URL bar transitions.
* **Pinch-Zoom:** Under pinch-zoom (Visual Viewport scale > 1.0), the `::backdrop` remains anchored to the Layout Viewport bounds, maintaining coverage over the entire scrollable document area visible within the visual frame.

#### B. Scrollbar Gutter Interactions
* **Root Scrollbars:** The `LayoutView` bounds used for fixed positioning corresponds to the client area (viewport minus classic non-overlay scrollbars). Therefore, `::backdrop` covers the visible content area up to the scrollbar track. 
* **Overlay Scrollbars:** On macOS/Android/ChromeOS, `::backdrop` extends *underneath* the overlay scrollbar thumb/track, achieving literal window-edge-to-edge coverage (`0,0` to `window.innerWidth, window.innerHeight`).

#### C. Out-of-Flow Scroll Offsets
Because the `::backdrop` is `position: fixed` to the `LayoutView`, root document scrolling does not shift the backdrop geometry. The PaintLayer for the backdrop is marked as fixed to the viewport, allowing the Blink Compositor (`cc`) to keep the layer stationary on the GPU during main-thread or compositor-thread scrolling.

#### D. Iframe Boundaries
If a popover is invoked inside an `<iframe>`, the `LayoutView` is scoped to that specific frame's document. The `::backdrop` will achieve full coverage of the **iframe's viewport**, not the outermost top-level browser viewport.

### 5. Identified Coverage Vulnerabilities (Author Overrides)
While Blink guarantees full viewport coverage by default, `::backdrop` is a stylable pseudo-element. Full coverage breaks if the author introduces:
* **Explicit Sizing:** Setting `width: 100vw; height: 100vh;` when classic scrollbars are present (causes horizontal overflow under the vertical scrollbar). `inset: 0` must be preserved.
* **Position Degradation:** Overriding `position: fixed` with `position: absolute`. While still in the top layer, `absolute` positioning anchors to the *Initial Containing Block* at scroll offset `0,0`. If the user scrolls down, the `::backdrop` will scroll out of view, breaking viewport coverage.

### 6. Audit Conclusion
**Status: PASS.** 
Blink’s implementation of the Popover `::backdrop` successfully enforces full viewport coverage by pairing Top Layer `LayoutView` containment overrides with `position: fixed; inset: 0;` UA rules. Compositor frame boundaries are respected, and ancestor stacking contexts are successfully bypassed.
