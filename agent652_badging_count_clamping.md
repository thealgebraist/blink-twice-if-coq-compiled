## 1. Normative W3C Badging API Specification Requirements

The W3C Badging API Specification defines mechanisms for web applications (both in foreground `Window` contexts and background `WorkerNavigator` contexts, such as Service Workers handling Web Push and Background Sync events) to set an application-wide badge on the application's icon in the host operating system.

### 1.1 WebIDL Interface (§4)
```webidl
[SecureContext]
interface mixin NavigatorBadge {
  Promise<undefined> setAppBadge(optional [EnforceRange] unsigned long long contents);
  Promise<undefined> clearAppBadge();
};

Navigator includes NavigatorBadge;
WorkerNavigator includes NavigatorBadge;
```

### 1.2 Processing Model for `setAppBadge(contents)` (§4.1)
When `setAppBadge(contents)` is invoked, the user agent executes the following normative steps:

1. **WebIDL Type Conversion (`[EnforceRange] unsigned long long`)**:
   - Let $V$ be the JavaScript `Number` converted from the argument `contents`.
   - If $V$ is `NaN`, $+\infty$, or $-\infty$, throw a `TypeError`.
   - Let $\text{intPart} = \text{truncate}(V)$.
   - If $\text{intPart} < 0$ or $\text{intPart} > 2^{64} - 1$, throw a `TypeError` (enforcing non-negative 64-bit unsigned integer bounds before entering the method implementation).
2. **Badge Value Determination**:
   - **Case 1 (`contents` is omitted / `undefined`)**: The user agent sets the application badge to the **"flag"** indicator (a boolean marker indicating activity without a specific count).
   - **Case 2 (`contents` is `0`)**: The user agent sets the application badge to **"nothing"** (semantically identical to invoking `clearAppBadge()`).
   - **Case 3 (`contents` is $> 0$)**: The user agent sets the application badge to the integer value `contents`.

### 1.3 The Clamping Property: `clamp_badge(contents) = max(1, contents)`
In formalizing the numeric payload of an *active numeric badge* (or when projecting arbitrary non-negative integer inputs onto the space of valid positive badge display counts), the mathematical property `clamp_badge(contents) = max(1, contents)` captures two critical boundary invariants:
1. **Active Numerical Badge Floor**: Whenever the display subsystem renders a numeric badge count, the displayed count $c$ must satisfy $c \ge 1$. A value of $0$ is never rendered as `"0"` on an icon; it is either intercepted to clear the badge or clamped to the minimal active indicator weight of $1$.
2. **Saturating/Clamping Projection**: For any non-negative input $n \in \mathbb{Z}_{\ge 0}$, projecting $n$ onto the domain of positive badge integers $\mathbb{Z}_{\ge 1}$ via `clamp_badge(n) = Z.max 1 n` preserves all valid counts $n \ge 1$ while clamping $0$ (and any hypothetical negative representation in signed IPC transport) to $1$.

## 2. Chromium Blink Implementation Details & Invariants

In Chromium, the Badging API is implemented in `third_party/blink/renderer/modules/badging/badge.cc` and communicates across the Mojo IPC boundary to the browser process via `third_party/blink/public/mojom/badging/badging.mojom`.

### 2.1 Mojo IPC Interface (`badging.mojom`)
```mojom
module blink.mojom;

// Value of the badge.
union BadgeValue {
  // Just a flag badge (no count). Represented by default uint8 0.
  uint8 flag;
  // A numerical badge. Must NOT be zero.
  uint64 number;
};

interface BadgeService {
  SetBadge(BadgeValue value);
  ClearBadge();
};
```
**Critical Mojo Invariant**: The `BadgeValue::NewNumber(uint64_t)` union variant has a strict security and rendering invariant: **the number must be strictly positive ($\ge 1$)**. Sending `BadgeValue::NewNumber(0)` across Mojo violates the protocol contract expected by `BadgingServiceImpl` in the browser process.

### 2.2 Blink Renderer Implementation (`badge.cc`)
In `third_party/blink/renderer/modules/badging/badge.cc`, Blink exposes two overloaded C++ entry points generated by the V8 bindings for `setAppBadge`:

```cpp
// Overload 1: Called when `contents` is omitted: navigator.setAppBadge()
ScriptPromise<IDLUndefined> Badge::setAppBadge(ScriptState* script_state,
                                               ExceptionState& exception_state) {
  badge_service()->SetBadge(mojom::blink::BadgeValue::NewFlag(0));
  return ToResolvedUndefinedPromise(script_state);
}

// Overload 2: Called when `contents` is provided: navigator.setAppBadge(contents)
ScriptPromise<IDLUndefined> Badge::setAppBadge(ScriptState* script_state,
                                               uint64_t content,
                                               ExceptionState& exception_state) {
  if (content == 0) {
    badge_service()->ClearBadge();
  } else {
    badge_service()->SetBadge(mojom::blink::BadgeValue::NewNumber(content));
  }
  return ToResolvedUndefinedPromise(script_state);
}
```

### 2.3 Architectural & Background Processing Invariants
1. **V8 `[EnforceRange]` Pre-Filter**: The V8 binding layer (`V8Navigator.cpp` / `V8WorkerNavigator.cpp`) executes `NativeValueTraits<IDLUnsignedLongLong>::NativeValue` with `EnforceRange`. Any signed negative number $x < 0$ or overflow $x > \text{UINT64\_MAX}$ throws a `TypeError` synchronously before `Badge::setAppBadge` is called.
2. **Non-Zero Mojo Numeric Payload**: Inside `Badge::setAppBadge(ScriptState*, uint64_t content, ...)`, the branch `if (content == 0)` routes $0$ to `ClearBadge()`. In the `else` branch, since `content` is an unsigned integer (`uint64_t`, so $\text{content} \ge 0$) and $\text{content} \neq 0$, it is guaranteed that $\text{content} \ge 1$, meaning $\text{content} = \max(1, \text{content})$.
3. **Defensive Numeric Clamping (`clamp_badge`)**: If a subsystem or OS bridge unconditionally constructs a numeric badge payload from an integer `contents`, applying `clamp_badge(contents) = max(1, contents)` guarantees that the Mojo `BadgeValue::NewNumber` invariant ($\text{number} \ge 1$) is unconditionally satisfied without underflow.
4. **Service Worker / Background Sync / Web Push Safety**: Because `WorkerNavigator` exposes `NavigatorBadge`, Service Workers frequently invoke `setAppBadge` inside `onpush` and `onsync` handlers. Ensuring that no invalid Mojo message (`NewNumber(0)`) is dispatched prevents browser-side `mojo::ReportBadMessage` termination of the Service Worker process during background execution.

## 3. Formal Specification & Verification in Rocq/Coq

Below is the complete, self-contained, and admitted-free Rocq/Coq formalization (`BlinkBadgingCountClampingSemantics.v`). It models the WebIDL `[EnforceRange]` conversion, the mathematical clamping function `clamp_badge(contents) = max(1, contents)`, the Blink `badge.cc` dispatch logic, the Mojo `BadgeValue` invariant, and background Service Worker queue processing.

```coq
(** * BlinkBadgingCountClampingSemantics.v
    Formal Verification of Chromium Blink Badging API Count Clamping & Dispatch
    Source: third_party/blink/renderer/modules/badging/badge.cc
    Specification: W3C Badging API §4.1 setAppBadge(contents)
*)

Require Import Coq.ZArith.ZArith.
Require Import Coq.Lists.List.
Require Import Coq.Bool.Bool.
Require Import Coq.micromega.Lia.

Import ListNotations.
Open Scope Z_scope.

(* ========================================================================== *)
(* 1. Constants and WebIDL [EnforceRange] Unsigned Long Long Bounds           *)
(* ========================================================================== *)

(** Maximum value of an unsigned 64-bit integer: 2^64 - 1 *)
Definition UINT64_MAX : Z := 18446744073709551615.

Lemma UINT64_MAX_pos : 1 <= UINT64_MAX.
Proof.
  unfold UINT64_MAX. lia.
Qed.

(** Predicate characterizing valid WebIDL [EnforceRange] unsigned long long values *)
Definition in_uint64_range (n : Z) : Prop :=
  0 <= n <= UINT64_MAX.

(** Decidable range check for WebIDL [EnforceRange] *)
Definition check_uint64_range (n : Z) : bool :=
  (0 <=? n) && (n <=? UINT64_MAX).

Lemma check_uint64_range_iff : forall n : Z,
  check_uint64_range n = true <-> in_uint64_range n.
Proof.
  intros n.
  unfold check_uint64_range, in_uint64_range.
  rewrite andb_true_iff.
  rewrite Z.leb_le, Z.leb_le.
  reflexivity.
Qed.

(* ========================================================================== *)
(* 2. Mathematical Clamping Model: clamp_badge(contents) = max(1, contents)   *)
(* ========================================================================== *)

(** The core clamping operation projecting any integer onto a positive integer (>= 1) *)
Definition clamp_badge (contents : Z) : Z :=
  Z.max 1 contents.

(** Optional clamp across uint64 upper bound as well *)
Definition clamp_badge_uint64 (contents : Z) : Z :=
  Z.min UINT64_MAX (clamp_badge contents).

(* ========================================================================== *)
(* 3. W3C Spec & Chromium Blink/Mojo Data Types                               *)
(* ========================================================================== *)

(** Input argument to navigator.setAppBadge(optional [EnforceRange] unsigned long long) *)
Inductive SetAppBadgeArg : Type :=
  | ArgOmitted : SetAppBadgeArg
  | ArgProvided (raw_contents : Z) : SetAppBadgeArg.

(** Mojo IPC BadgeValue union (third_party/blink/public/mojom/badging/badging.mojom) *)
Inductive MojoBadgeValue : Type :=
  | MojoFlag : MojoBadgeValue
  | MojoNumber (n : Z) : MojoBadgeValue.

(** Mojo IPC BadgeService messages sent from Blink Renderer to Browser process *)
Inductive MojoBadgeIPC : Type :=
  | IPC_SetBadge (val : MojoBadgeValue) : MojoBadgeIPC
  | IPC_ClearBadge : MojoBadgeIPC.

(** Result of calling Badge::setAppBadge in Blink *)
Inductive BlinkResult : Type :=
  | BlinkThrowTypeError : BlinkResult
  | BlinkResolved (ipc : MojoBadgeIPC) : BlinkResult.

(** Application Badge State stored in the Browser Process / OS Shell *)
Inductive AppBadgeState : Type :=
  | BadgeNothing : AppBadgeState
  | BadgeFlag : AppBadgeState
  | BadgeCount (c : Z) : AppBadgeState.

(* ========================================================================== *)
(* 4. Invariants on Mojo IPC and Browser Badge State                          *)
(* ========================================================================== *)

(** Normative Mojo invariant: BadgeValue::number MUST be a positive integer (>= 1)
    and within uint64 bounds. *)
Definition valid_mojo_badge_value (v : MojoBadgeValue) : Prop :=
  match v with
  | MojoFlag => True
  | MojoNumber n => 1 <= n <= UINT64_MAX
  end.

Definition valid_mojo_ipc (msg : MojoBadgeIPC) : Prop :=
  match msg with
  | IPC_SetBadge v => valid_mojo_badge_value v
  | IPC_ClearBadge => True
  end.

(** Normative Browser/OS state invariant: an active numeric badge count is >= 1 *)
Definition valid_app_badge_state (st : AppBadgeState) : Prop :=
  match st with
  | BadgeNothing => True
  | BadgeFlag => True
  | BadgeCount c => 1 <= c <= UINT64_MAX
  end.

(* ========================================================================== *)
(* 5. Blink Implementation Models (badge.cc)                                  *)
(* ========================================================================== *)

(** Model 1: Exact Blink badge.cc implementation with 0 -> ClearBadge branch
    and positive clamping identity in the numeric branch. *)
Definition blink_set_app_badge (arg : SetAppBadgeArg) : BlinkResult :=
  match arg with
  | ArgOmitted =>
      BlinkResolved (IPC_SetBadge MojoFlag)
  | ArgProvided contents =>
      if check_uint64_range contents then
        if contents =? 0 then
          BlinkResolved IPC_ClearBadge
        else
          BlinkResolved (IPC_SetBadge (MojoNumber contents))
      else
        BlinkThrowTypeError
  end.

(** Model 2: Clamped numeric dispatch (where any provided in-range contents is
    explicitly passed through clamp_badge when constructing a numeric badge, or
    where the positive branch explicitly applies clamp_badge). *)
Definition blink_set_app_badge_clamped (arg : SetAppBadgeArg) : BlinkResult :=
  match arg with
  | ArgOmitted =>
      BlinkResolved (IPC_SetBadge MojoFlag)
  | ArgProvided contents =>
      if check_uint64_range contents then
        if contents =? 0 then
          BlinkResolved IPC_ClearBadge
        else
          BlinkResolved (IPC_SetBadge (MojoNumber (clamp_badge contents)))
      else
        BlinkThrowTypeError
  end.

(** Model 3: Direct forced-numeric badge construction using clamp_badge_uint64 *)
Definition make_clamped_mojo_number (raw : Z) : MojoBadgeValue :=
  MojoNumber (clamp_badge_uint64 raw).

(** Browser-side state transition upon receiving a Mojo IPC message *)
Definition apply_mojo_ipc (st : AppBadgeState) (msg : MojoBadgeIPC) : AppBadgeState :=
  match msg with
  | IPC_ClearBadge => BadgeNothing
  | IPC_SetBadge MojoFlag => BadgeFlag
  | IPC_SetBadge (MojoNumber n) => BadgeCount (clamp_badge n)
  end.

Definition
