**AGENT 474 — AUDIT REPORT: BLINK CASCADE ORIGIN PRIORITY**
**Target Architecture:** Chromium / Blink Rendering Engine (`third_party/blink/renderer/core/css/cascade_priority.h`)
**Subject:** Total Ordering of CSS Cascade Origins and Layers

---

### 1. Executive Summary
In the Blink rendering engine, the resolution of CSS declarations is governed by a strict total ordering system before specificity and order-of-appearance are evaluated. This ordering is determined by the **Cascade Origin**, the **Importance** (`!important`), the **Shadow DOM Context** (Tree Order), and **Cascade Layers** (`@layer`). 

Note on the "Inversion" Principle: For standard (normal) declarations, priority ascends from User-Agent to Author. For `!important` declarations, the origin priority (and layer priority) is strictly inverted, ascending from Author to User-Agent.

---

### 2. Total Ordering Matrix (Lowest to Highest Priority)

Below is the absolute ordering of cascade origins as resolved by Blink’s `StyleCascade`, listed from **1 (Lowest Priority / Applied First)** to **12 (Highest Priority / Winning Override)**.

#### **PHASE I: Normal Declarations**
* **01. User-Agent (Normal)** 
  * *Source:* Blink default stylesheets (`html.css`, `quirks.css`, etc.).
* **02. User (Normal)** 
  * *Source:* OS-level accessibility styles or browser-injected user stylesheets.
* **03. Author (Normal)** 
  * *Source:* Document stylesheets (`<style>`, `<link>`), inline styles (`style=""`), and `@keyframes` from the page author.
  * *Sub-ordering:* Governed by Shadow Tree context and `@layer` order (see Section 3).

#### **PHASE II: Active Animations**
* **04. CSS Animations & Web Animations API**
  * *Source:* Currently ticking `@keyframes` or JS-driven `Element.animate()` effects.
  * *Blink Implementation Note:* Blink evaluates base style, then applies active animations over normal author styles, regardless of specificity.

#### **PHASE III: Important Declarations (Origin Inversion)**
* **05. Author (`!important`)**
  * *Source:* Document/inline styles flagged with `!important`.
  * *Note:* Overrides active CSS animations.
* **06. Override / Inspector (`!important`)**
  * *Source:* DevTools inspector overrides, SVG presentation attribute overrides.
* **07. User (`!important`)**
  * *Source:* User-defined `!important` rules.
* **08. User-Agent (`!important`)**
  * *Source:* Browser internal rules critical for functionality/security (e.g., `display: none !important` on `<datalist>` or fullscreen API constraints).

#### **PHASE IV: Transitions**
* **09. CSS Transitions**
  * *Source:* Active interpolations generated by the `transition` property.
  * *Audit Note:* Per the CSS Cascade specification implemented in Blink, active transitions take precedence over all `!important` rules to ensure smooth visual interpolation between states, even when transitioning to/from an `!important` state.

---

### 3. Intra-Origin Sub-Ordering (The "Author" Origin Breakdown)

Within **Origin 03 (Author Normal)** and **Origin 05 (Author `!important`)**, Blink must resolve conflicts across Shadow DOM boundaries (Encapsulation Context) and Cascade Layers (`@layer`). 

Blink packs these values into a 64-bit integer (`CascadePriority`) to compare them in $O(1)$ time. The sub-ordering is as follows (Lowest to Highest):

#### **A. Within Author (Normal) [Origin 03]:**
1. **Outer Tree (Document) — Declared `@layer`s** (ordered by first appearance).
2. **Outer Tree (Document) — Unlayered Styles** (implicit top-level layer).
3. **Inner Tree (Shadow DOM) — Declared `@layer`s** (styles inside a component).
4. **Inner Tree (Shadow DOM) — Unlayered Styles**.
5. **Inline Styles (`style="..."`)** (Treated as the highest normal priority within its respective tree context).

*(Note: Styles applied via `::slotted()` or `:host` belong to the Inner Tree context, so they lose to Outer Tree rules in Normal mode).*

#### **B. Within Author (`!important`) [Origin 05]:**
*Context and Layer priorities completely invert.*
1. **Inline Styles (`style="... !important"`)** (Within its tree context).
2. **Inner Tree (Shadow DOM) — Unlayered `!important`**.
3. **Inner Tree (Shadow DOM) — Declared `@layer` `!important`** (First declared layer wins).
4. **Outer Tree (Document) — Unlayered `!important`**.
5. **Outer Tree (Document) — Declared `@layer` `!important`** (First declared layer has the absolute highest Author priority).

---

### 4. Blink Source-Level Representation (`CascadePriority`)

In Blink’s C++ implementation, the total ordering is achieved by bit-packing the cascade metadata so that a simple integer comparison (`a > b`) yields the winning declaration:

```text
[High Bits] -----------------------------------------------------------------> [Low Bits]
[IsTransition] [Origin & Importance] [TreeOrder (Shadow)] [LayerOrder] [InlineStyle] [Position]
```

* **`Origin & Importance`:** Mapped to the `CascadeOrigin` enum (in `cascade_origin.h`), where `kUserAgent` = 1, `kUser` = 2, `kAuthorPresentationalHint` = 3, `kAuthor` = 4, `kAnimation` = 5, `kAuthorImportant` = 6, `kUserImportant` = 7, `kUserAgentImportant` = 8, `kTransition` = 9.
* **`TreeOrder`:** Inverted via bitwise NOT (`~`) if the `is_important` bit is set.
* **`LayerOrder`:** Inverted via bitwise NOT (`~`) if the `is_important` bit is set.

**Audit Status:** Complete. Blink's bit-packing mechanism strictly enforces W3C CSS Cascading and Inheritance Level 5 specifications.
