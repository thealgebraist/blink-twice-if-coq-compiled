## 1. Normative Specification Requirements (RFC 9111 §4.2)

Per **IETF RFC 9111 §4.2 (Freshness)**, a stored HTTP response is considered *fresh* if its age has not yet exceeded its freshness lifetime. The primary mechanism for origin servers to explicitly dictate this lifetime is the `Cache-Control: max-age` response directive.

### 1.1 Freshness Lifetime Calculation (§4.2.1)
A cache calculates the `freshness_lifetime` of a response by evaluating several heuristics and explicit headers in strict priority order:
1. If the cache is shared and the `s-maxage` response directive is present, use its value.
2. If the `max-age` response directive is present, use its value (in seconds).
3. If the `Expires` response header field is present, use its value minus the value of the `Date` response header field.
4. Otherwise, a heuristic freshness lifetime might be applicable.

For private client caches (such as Chromium's Blink memory cache and the `net/` disk cache), priority rule (2) dominates when `max-age` is supplied.

### 1.2 Freshness Determination (§4.2)
The determination of whether a response is fresh is governed by the inequality:
$$\text{response\_is\_fresh} \iff \text{freshness\_lifetime} > \text{current\_age}$$

Equivalently, defining remaining freshness $\Delta_{\text{fresh}}$ as:
$$\Delta_{\text{fresh}} = \text{freshness\_lifetime} - \text{current\_age}$$
a cached response can be served without network revalidation (barring `no-cache` or `must-revalidate` overrides) if and only if:
$$\Delta_{\text{fresh}} > 0$$

### 1.3 Age Calculation (§4.2.3)
The `current_age` of a stored response is the time elapsed since the response was generated by (or validated with) the origin server, adjusted for network transit delays via the `Age` header, response time, request time, and current resident time in the cache. By normative definition, `current_age` $\ge 0$ and `max-age` (parsed as `delta-seconds`, `1*DIGIT`) $\ge 0$.

## 2. Chromium & Blink Implementation Details

In Chromium, HTTP header parsing and freshness lifetime evaluation are implemented in `net/http/http_response_headers.cc` and exposed to Blink's resource loading pipeline (`third_party/blink/renderer/platform/loader/fetch/`) via `ResourceResponse`.

### 2.1 `HttpResponseHeaders::GetFreshnessLifetimes`
In `net/http/http_response_headers.cc`, freshness is computed using `base::TimeDelta` (which wraps a 64-bit signed microsecond counter `int64_t`):

```cpp
// Simplified representation of net/http/http_response_headers.cc
FreshnessLifetimes HttpResponseHeaders::GetFreshnessLifetimes(
    Time response_time) const {
  FreshnessLifetimes lifetimes;
  // Check for no-cache / no-store directives first...
  
  // RFC 9111 §4.2.1: max-age directive overrides Expires header.
  if (GetMaxAgeValue(&lifetimes.freshness))
    return lifetimes;

  // Fallback to Expires - Date ...
}
```

### 2.2 `HttpResponseHeaders::GetMaxAgeValue`
The `GetMaxAgeValue` method parses the `max-age` token from `Cache-Control`. It strictly requires non-negative integer seconds and saturates on overflow to `base::TimeDelta::Max()`.

### 2.3 Validation in `HttpCache::Transaction` and Blink `Resource`
When evaluating whether a cached entry requires revalidation (`RequiresValidation` in `net/http/http_cache_transaction.cc`):
```cpp
base::TimeDelta current_age = headers->GetCurrentAge(
    request_time, response_time, base::Time::Now());
base::TimeDelta freshness = lifetimes.freshness;

bool is_fresh = (freshness > current_age); // Equivalent to (freshness - current_age) > 0
```

### 2.4 Implementation Invariants
1. **Non-negativity of `max_age`**: `GetMaxAgeValue` rejects negative tokens; `lifetimes.freshness >= 0`.
2. **Non-negativity of `current_age`**: Clock skew compensation in `GetCurrentAge` clamps apparent age to `std::max(0, ...)`, ensuring `current_age >= 0`.
3. **Strict Inequality at Boundary**: When `max_age == current_age` (including `max-age=0` at `current_age=0`), `freshness - current_age == 0`, which evaluates `is_fresh` to `false`. This guarantees `max-age=0` forces immediate stale status.
4. **Monotonic Expiration**: As time progresses (`current_age` increases monotonically while `max_age` remains constant), `freshness` monotonically decreases. Once a response transitions from fresh to stale, it cannot spontaneously become fresh again without revalidation.

## 3. Formal Specification in Rocq (Coq)

Below is the complete, self-contained formalization of `BlinkHTTPCacheFreshnessLifetimeSemantics.v`. We model time values using arbitrary-precision integers (`Z` from `ZArith`) representing discrete time ticks (seconds or microseconds, preserving isomorphism under scaling).

```coq
(** * BlinkHTTPCacheFreshnessLifetimeSemantics.v
    Formalization of RFC 9111 §4.2 HTTP Cache-Control max-age freshness
    lifetime semantics as implemented in Chromium's net/http/http_response_headers.cc.
*)

From Coq Require Import ZArith.
From Coq Require Import Bool.
From Coq Require Import Lia.

Open Scope Z_scope.

(** ** 1. Core Data Types and Directives *)

(** Time and durations are modeled as integers (Z). 
    In Chromium, this corresponds to [base::TimeDelta] (int64_t microseconds)
    or RFC 9111 delta-seconds. *)
Definition TimeDelta := Z.

(** Representation of a parsed Cache-Control max-age directive and current age
    context for a cached HTTP response. *)
Record CacheEntryContext := mkCacheEntryContext {
  max_age : TimeDelta;
  current_age : TimeDelta;
}.

(** Well-formedness predicate corresponding to Chromium's parser invariants in
    [HttpResponseHeaders::GetMaxAgeValue] and [HttpResponseHeaders::GetCurrentAge]. *)
Definition wf_context (ctx : CacheEntryContext) : Prop :=
  ctx.(max_age) >= 0 /\ ctx.(current_age) >= 0.

(** ** 2. Freshness Semantics (Definitions & Executable Functions) *)

(** Remaining freshness margin: freshness = max_age - current_age *)
Definition compute_freshness (max_a curr_a : TimeDelta) : TimeDelta :=
  max_a - curr_a.

Definition entry_freshness (ctx : CacheEntryContext) : TimeDelta :=
  compute_freshness ctx.(max_age) ctx.(current_age).

(** Decidable boolean predicate for freshness: is_fresh iff freshness > 0 *)
Definition is_fresh_b (max_a curr_a : TimeDelta) : bool :=
  Z.gtb (compute_freshness max_a curr_a) 0.

Definition entry_is_fresh_b (ctx : CacheEntryContext) : bool :=
  is_fresh_b ctx.(max_age) ctx.(current_age).

(** Propositional specification of freshness per RFC 9111 §4.2 *)
Definition is_fresh_prop (max_a curr_a : TimeDelta) : Prop :=
  compute_freshness max_a curr_a > 0.

Definition rfc9111_fresh_spec (max_a curr_a : TimeDelta) : Prop :=
  max_a > curr_a.
```

## 4. Concrete Theorems and Complete Proofs

We now state and prove the core correctness, reflection, boundary, and monotonicity theorems. Every proof is complete and verified without `Admitted` or axioms.

```coq
(** ** 3. Formal Theorems and Proofs *)

(** Theorem 1: Boolean-Propositional Reflection Equivalence.
    Proves that the executable decision procedure [is_fresh_b] is sound and
    complete with respect to the mathematical property [freshness > 0]. *)
Theorem is_fresh_reflection : forall (max_a curr_a : TimeDelta),
  is_fresh_b max_a curr_a = true <-> is_fresh_prop max_a curr_a.
Proof.
  intros max_a curr_a.
  unfold is_fresh_b, is_fresh_prop, compute_freshness.
  rewrite Z.gtb_ltb.
  rewrite Z.ltb_lt.
  lia.
Qed.

(** Theorem 2: Equivalence to Stale Complement.
    Proves that [is_fresh_b = false] iff remaining freshness is non-positive. *)
Theorem is_stale_reflection : forall (max_a curr_a : TimeDelta),
  is_fresh_b max_a curr_a = false <-> compute_freshness max_a curr_a <= 0.
Proof.
  intros max_a curr_a.
  unfold is_fresh_b, compute_freshness.
  rewrite Z.gtb_ltb.
  rewrite Z.ltb_ge.
  lia.
Qed.

(** Theorem 3: RFC 9111 §4.2 Direct Inequality Equivalence.
    Proves that Chromium's [freshness = max_age - current_age; freshness > 0]
    formulation is strictly equivalent to RFC 9111's [freshness_lifetime > current_age]. *)
Theorem freshness_rfc9111_equivalence : forall (max_a curr_a : TimeDelta),
  is_fresh_b max_a curr_a = true <-> rfc9111_fresh_spec max_a curr_a.
Proof.
  intros max_a curr_a.
  rewrite is_fresh_reflection.
  unfold is_fresh_prop, rfc9111_fresh_spec, compute_freshness.
  lia.
Qed.

(** Theorem 4: Zero Max-Age Immediate Expiration (Cache-Control: max-age=0).
    Per RFC 9111, [max-age=0] mandates that the cache MUST NOT serve the
    response without revalidation for any well-formed (non-negative) current age. *)
Theorem zero_max_age_always_stale : forall (ctx : CacheEntryContext),
  wf_context ctx ->
  ctx.(max_age) = 0 ->
  entry_is_fresh_b ctx = false.
Proof.
  intros ctx [Hmax Hcurr] Hzero.
  unfold entry_is_fresh_b.
  apply is_stale_reflection.
  unfold compute_freshness.
  lia.
Qed.

(** Theorem 5: Boundary Expiration at Exact Lifetime.
    When [current_age] reaches [max_age], remaining freshness is exactly 0
    and the response transitions to stale. *)
Theorem boundary_age_is_stale : forall (t : TimeDelta),
  compute_freshness t t = 0 /\ is_fresh_b t t = false.
Proof.
  intro t.
  split.
  - unfold compute_freshness. lia.
  - apply is_stale_reflection. unfold compute_freshness. lia.
Qed.

(** Theorem 6: Temporal Monotonicity of Freshness Decay.
    As time advances by [delta >= 0], remaining freshness decreases monotonically,
    and a stale response cannot become fresh without updating [max_age] via revalidation. *)
Theorem freshness_monotonic_decay : forall (max_a curr_a delta : TimeDelta),
  delta >= 0 ->
  compute_freshness max_a (curr_a + delta) <= compute_freshness max_a curr_a.
Proof.
  intros max_a curr_a delta Hdelta.
  unfold compute_freshness.
  lia.
Qed.

(** Theorem 7: Irreversibility of Staleness Under Time Progression.
    If an entry is stale at [curr_a], it remains stale at [curr_a + delta] for all [delta >= 0]. *)
Theorem staleness_is_irreversible : forall (max_a curr_a delta : TimeDelta),
  delta >= 0 ->
  is_fresh_b max_a curr_a = false ->
  is_fresh_b max_a (curr_a + delta) = false.
Proof.
  intros max_a curr_a delta Hdelta Hstale.
   rewrite is_stale_reflection in *.
  unfold compute_freshness in *.
  lia.
Qed.

(** Theorem 8: Upper Bound on Remaining Freshness for Well-Formed Contexts.
    For any well-formed cache entry, remaining freshness never exceeds [max_age]. *)
Theorem wf_freshness_bounded_by_max_age : forall (ctx : CacheEntryContext),
  wf_context ctx ->
  entry_freshness ctx <= ctx.(max_age).
Proof.
  intros ctx [Hmax Hcurr].
  unfold entry_freshness, compute_freshness.
  lia.
Qed.
```
